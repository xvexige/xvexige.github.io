## 写在前面

2026 年 1 月，我开始了人生第一段实习，在一家做结构健康监测的公司做物联网云平台（内部代号 tongganyun-v4）的前端开发。这段实习分两个阶段：第一阶段四周（1.12 – 2.6），春节后又续了第二阶段（3 月起）。

当时留下了不少记录——周报、每日 TODO、学习笔记、踩坑笔记，还有一份写给公司的实习总结。收尾这几天把它们从头读了一遍，决定写成这个复盘系列，一是把散落的记录串成线，二是给未来翻旧账的自己留个路标。

这是第一篇，讲整个实习的脉络和成长。后面三篇是技术向的深潜：

- **（二）一个表单校验的三次迭代**——从 ngModel 到响应式表单再到 Signal，也是我理解 Angular 变化检测的过程
- **（三）组件封装与 ng-zorro 样式定制体系**——分页组件二次封装和 override.css 样式库的建设
- **（四）踩坑记录与工程习惯的养成**——Git 三连坑、白屏排查、和设计稿"打架"

## 起点：进组之前我会什么

去之前我的底子：HTML/CSS/JS 基础，学过一点 Java 和 Spring（后来博客里那篇 petclinic 笔记就是那个时期的），TypeScript 只听说过，Angular 完全没碰过，Tailwind 和 ng-zorro 也只是听说过名字。

组里给我的定位很明确：**Angular 19 + Tailwind CSS + ng-zorro-antd** 技术栈，负责物联网云平台的几个前端功能模块。于是第一周的任务不是写业务，而是把这三样东西在最短时间内啃下来。

## 第一阶段：四周流水账

### 第一周（1.12 – 1.16）：边学边写第一个弹窗

第一周的节奏大概是：

- **Day 1**：配环境。nvm / node / npm 版本对齐，clone 代码跑通
- **Day 2 – 3**：过 Angular 官方训练场（angular.dev 的 Learn Angular 教程），重点啃了组件、`@if` / `@for` 新语法、属性绑定、依赖注入、管道；同时在本地起了个练手项目，照着 UI 稿写"下载数据"弹窗
- **Day 4**：clone 正式项目 tongganyun-v4 到本地，熟悉 core / shared / features 三层目录结构，给云监控配了路由
- **Day 5**：啃 Tailwind 文档，照着 GitHub 的页面仿写样式

这一周的产出是**数据下载弹窗的初版**——功能能跑，但代码很糙：满屏 `div` + 手写 CSS 类，组件库的特性基本没用上，也没有任何表单校验。

现在回头看，这个"糙"是必经的：先不管写得好不好，把功能闭环跑通，先建立"我能交付"的信心。**初版的意义不是质量，是熟悉整条开发链路。**

### 第二周（1.19 – 1.23）：结构物列表页，第一次独立扛一个页面

这一周开始独立开发**结构物列表页面**，拆成两个组件：工具栏（搜索 + 状态筛选 + 添加按钮）和列表项（卡片展示、地图标记、状态权限、分页）。

技术上第一次大量用 Angular 19 的 **Signal** 管理状态：

```typescript
currentPage = signal(1);
pageSize = signal(10);

// 派生状态：先按状态排序，再分页，再补上按钮权限
paginatedStructures = computed(() => {
  // ...排序 → 切片 → map 出 canEdit / canDelete / canArchive
});
```

`computed()` 自动追踪依赖这件事，和我在 Vue 里理解的"计算属性"对上了，上手很快。

这一周印象最深的其实不是代码，是三件事：

1. **和设计稿冲突**：设计稿给右侧列表写死了 `h-[736px]`，但真实业务里列表高度应该随视口变化。我最终放弃硬编码，改成 `h-full` + Flex 上下文控制。这是我第一次"质疑设计稿"——设计稿是静态快照，页面是活的。
2. **被 Vim 卡住**：git merge 进了 Vim 交互界面不知道怎么退出，流程卡在那里。查了文档才知道 `:wq`。现在觉得好笑，当时是真的慌。
3. **封装了第一个通用组件**：原生 `nz-pagination` 样式难定制、功能冗余，我把它和 `nz-select` 二次封装成了自己的分页组件，后来在多个页面复用。（细节在第三篇展开）

### 第三周（1.26 – 1.30）：重构自己的代码

第三周先写了**数据推送弹窗**（TCP/HTTP/MQTT 推送规则列表、RTU 选择、Switch 开关），然后做了一件当时觉得"没必要"、后来觉得最重要的事：**重构第一周写的数据下载弹窗**。

三周前写的东西已经看不下去了——这本身就是一个信号，说明我在这三周里变强了。重构内容：

- `ngModel` 模板驱动表单 → **Reactive Forms 响应式表单**
- 手写 CSS → **Tailwind 原子类**
- 没有校验 → **动态表单校验**（必填规则随用户选择切换）
- 散落的样式 → 集中到全局的 **`ng-zorro-override.css`** 样式库

### 第四周（2.2 – 2.6）：性能优化，两次迭代

第四周在上周重构的基础上继续打磨表单校验的性能问题。核心矛盾：为了在模板里显示校验状态，我在模板里调用了一堆方法，而 **Angular 的变化检测会在每个周期执行模板里的所有表达式**——这些方法每秒被调用几十上百次，纯属浪费。

两次迭代：第一版把方法封装得更整洁，但治标不治本；第二版把所有校验状态收进一个 **Signal 对象**，用 RxJS `merge` 统一监听表单变化，模板直接读 Signal，方法调用归零。这个过程逼着我真正理解了 Angular 的变化检测机制。（完整过程在第二篇展开）

这周还新写了"添加结构物"弹窗，算是把响应式表单的套路又练了一遍。

## 第二阶段（3 月）：从"写功能"到"做基建"

春节后回来，工作内容升级了，几个代表：

- **统一错误检校服务 `FormValidatorService`**：把散落在各个弹窗里的 `markAsTouched` + 错误提示逻辑收成一个服务，`markControlsAsTouched(form)` 一行搞定，还能批量收集错误提示。这是从"自己写好"到"给团队写好"的转变
- **添加/编辑项目弹窗**：接触了 **JSON Patch**（`op: replace` 增量提交）、地址模糊搜索回填、图片上传的 `forkJoin` / `switchMap` / `catchError` 组合——RxJS 从"知道"变成"在用"
- **结构物详情页的自定义下拉**：原生 `nz-select` 满足不了带状态色的定制需求，用"按钮 + 下拉列表 + 点击外部关闭"自己实现了一个
- **项目列表的空缺省页面 + 冻结列表格**：左侧冻结列 + 右侧冻结操作列 + 横向滚动的表格布局，以及列表为空时的占位页
- **git stash 当版本管理用**：多份 stash 对应多组修改，`git stash list` / `show -p` / `drop` 管理得明明白白

这个阶段还被导师 review 了几次代码，其中一句反馈我记到现在：**"不要在模板中调用方法，使用计算属性、封装对象或信号。"**——和第四周自己踩过的坑正好呼应，说明那个坑踩得值。

## 交付了什么

按当时的统计，两个阶段合计：

**功能模块**

- 结构物列表页面（工具栏 + 列表项 + 地图集成）
- 数据下载弹窗（含一次重构、两次性能迭代）
- 数据推送弹窗
- 添加结构物 / 添加项目弹窗（含编辑回显、增量提交）
- 自定义分页组件（多页面复用）

**基建**

- `ng-zorro-override.css` 样式库：8+ 个 ng-zorro 组件的统一定制，CSS 变量管理颜色，`custom-` 前缀约束作用域
- 基于 Signal 的高效表单校验方案
- 统一错误检校服务 `FormValidatorService`

代码量大约 TS 1400+ 行、HTML 900+ 行、CSS 650+ 行。数字不大，但每一行都是真刀真枪交付到企业项目里的。

## 三个转变

如果要用一句话概括这段实习的成长，是三个转变：

**1. 从"能用就行"到"写好代码"。** 第一周的我满足于功能跑通；第四周的我会主动审视模板里每个方法调用的性能成本。中间隔的是一次重构和两次迭代——**写好代码的能力不是学出来的，是把自己的烂代码改出来的。**

**2. 从"完成功能"到"考虑维护"。** 建 override.css 样式库、封装分页组件、抽 FormValidatorService，这些多做的部分当下没有直接产出，但让后面的开发越来越快。我开始理解"代码是写给半年后的自己和同事看的"。

**3. 从"单打独斗"到"团队协作"。** Git 分支协作、被 code review、接受反馈再改。被指出问题的瞬间不好受，但每次改完都明显变好。

还有一个没写进公司总结里的第四个转变：**从"照抄设计稿"到"质疑设计稿"。** 736px 那件事之后，我看到设计稿的第一反应不再是"怎么还原它"，而是"这个设计在动态数据下合理吗"。

## 不足与后续

当时给自己列的改进方向，现在回头看依然成立：

| 方面 | 不足 | 计划 |
| --- | --- | --- |
| 技术深度 | RxJS 只会用常用操作符，原理不熟 | 系统学 RxJS，理解变化检测机制 |
| 测试 | 实习期间零测试 | 补 Jasmine / Karma / Playwright |
| 工程化 | 构建工具、CI/CD 只停留在"知道" | 学 Vite/Webpack、Docker、自动化部署 |
| 设计 | 只能还原，不能创造 | 学 UI/UX 原则，培养审美 |

## 写在最后：记录的价值

这段实习我最大的"元习惯"收获是**记录**：每日 TODO 打勾、每周三段式周报（完成 / 遇到问题 / 怎么解决）、随手的学习笔记、原代码与新代码的对比存档。当时只觉得是任务，回头复盘时才发现，这些记录才是最值钱的——没有它们，很多细节早就蒸发了。

如果你也是刚开始第一段实习，我的建议就一条：**把每天的坑记下来，不管多小。** Vim 怎么退出这种事，记下来是笔记，没记下来就只是又一次慌乱。
